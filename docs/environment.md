# 環境構築手順

この拡張が正しく動作するための、拡張の外側の設定。
別のマシンに環境を再構築する場合もこの手順に従う。

---

## 1. 入力ソースの登録

設定 → キーボード → 入力ソース で、以下の2つを登録する。

1. 英語 (US)
2. 日本語 (Mozc)

確認：

```bash
gsettings get org.gnome.desktop.input-sources sources
# => [('xkb', 'us'), ('ibus', 'mozc-jp')]
```

物理キーボードが US 配列であることも確認する。

---

## 2. Mozc を常にひらがなモードで起動させる

### 背景

Mozc は既定で「直接入力」モードで起動する。US配列には英数キーがないため、
一度直接入力に落ちると復帰が難しい。また拡張の表示（あ）と実際の入力状態
（英数）が食い違い、子どもにとって最も混乱する状態になる。

`active_on_launch` は「IBus 起動時に Mozc を自動的に有効化するかどうか」の
フラグで、`True` にすると起動と同時にひらがな入力が使える状態で立ち上がる。

### 手順

```bash
nano ~/.config/mozc/ibus_config.textproto
```

`engines { ... }` ブロックの**外側**に以下を記述する。
既存の `active_on_launch: False` があれば `True` に書き換える。

```
active_on_launch: True
```

反映：

```bash
ibus write-cache; ibus restart
```

### 注意

`~/.mozc/ibus_config.textproto` が存在する場合、そちらが
`~/.config/mozc/` より優先される。古い環境からのアップグレードで
残っていることがあるので確認する。

```bash
ls ~/.mozc/ 2>/dev/null
```

出力があれば、そちらのファイルを編集する。

### GUI には該当設定がない

Mozc のプロパティ画面には起動時モードの設定項目は存在しない。
設定ファイルを直接編集するしかない。

---

## 3. Mozc のキー設定から直接入力への経路を削除

Mozc プロパティを開く。

```bash
/usr/lib/ibus-mozc/ibus-setup-mozc-jp
```

「一般」タブ →「キー設定の選択」→「編集」。
コマンド列のヘッダをクリックしてソートすると探しやすい。

コマンドが以下になっている行を**すべて**削除する。

- `IMEを無効化`
- `入力モードを直接入力に切り替え`
- `IMEを有効化/無効化`（存在すれば）

これで Mozc 内部のモードはひらがなに固定され、システム全体の状態は
「英語(US)」か「Mozc(ひらがな)」の2つだけになる。

### 削除しないもの

F7〜F10 に割り当てられた変換コマンド（カタカナ変換・半角英数変換など）は
モード切替ではなく入力中の単語に対する変換機能なので、残しておく。

---

## 4. 動作確認

```bash
# ひらがなで起動するか
# → ログアウト→ログイン後、テキストエディタで aiueo と打つ

# IBus 再起動後も維持されるか
ibus restart
```

---

## 5. トラブルシューティング

### 直接入力に落ちてしまう

- `active_on_launch` が `True` になっているか
- `~/.mozc/ibus_config.textproto` が優先されていないか
- Mozc のキー設定に `IMEを無効化` が残っていないか

### 表示と実際の入力状態が食い違う

Mozc 内部のモードがひらがな以外になっている可能性が高い。
トレイメニューから一度「ひらがな」を選び直す。
再発する場合は 3 の削除が不完全。
